# Etapa 1 - BM25 (busca lexical)

> Live-build. Roteiro §6. A primeira coisa que nasce no palco. ~8-10 min.

## Objetivo

Adicionar a perna **lexical** da busca híbrida: dado o perfil da Solípse, retornar um ranking
de empresas que casam por **palavra literal** (setor, região, porte, termos como "B2B SaaS",
"BH", "média"). É o que a dense borra - a dense pega significado e perde o termo exato.

A saída é um `top-N` de empresas com score BM25, no mesmo formato que a dense já devolve, pra
o RRF (etapa 2) conseguir fundir os dois.

## Depende de

- **Dense retrieval (pré-build)** já devolvendo um ranking - serve de espelho de formato.
- Banco populado com as descrições das empresas e o índice de full-text search criado no
  Fluxo 0 (pré-build).

> FTS é uma variação de BM25 e a base já está nele. Sem nova dependência.

## Conceito essencial

BM25 trata texto como saco de palavras e pontua por match literal, com três pesos:

- **Palavra rara que casa** pesa muito (IDF alto); palavra comum quase não pesa.
- **Frequência satura** - a 10ª menção de "node" não vale 10x a 1ª.
- **Documento curto** que casa ganha bônus; longo é penalizado proporcionalmente.

Fórmula (soma sobre as palavras da query):

```
BM25(q, doc) = Σ IDF(palavra) * TF_norm(palavra, doc)
TF_norm = TF * (k1 + 1) / (TF + k1 * (1 - b + b * |doc| / avgdl))
IDF     = log( (N - df + 0.5) / (df + 0.5) + 1 )
```

Defaults: `k1 = 1.2`, `b = 0.75`. Quase nunca precisam de tuning.

**Exemplo numérico** (query `"node"`, 4 docs de 4 palavras, `N=4`, `avgdl=4`):

| Doc | conteúdo | TF | BM25 |
|-----|----------|----|------|
| A | "frontend dev react node" | 1 | 0.36 |
| B | "senior node typescript aws" | 1 | 0.36 |
| C | "node node node tutorial" | 3 | 0.56 |
| D | "java spring boot kafka" | 0 | 0 |

Ranking: C > A = B > D. Repare que 3 menções no C valeram **1.57** de TF, não 3 - a saturação
evita spam de palavra-chave.

## Gotchas

- **Stemming/stopwords**: o dicionário `portuguese` do Postgres já trata "desenvolvedor"/
  "desenvolvedora" e remove "de", "a", "para". Use-o explicitamente.
- **Tokenização de termos compostos**: "node.js" vs "node" + "js" muda o resultado. Decida e
  seja consistente com o que o Fluxo 0 indexou.
- **Escala incomparável com a dense**: o score BM25 (0.36, 12.7...) não é comparável com cosine
  (0-1). **Não some os dois** - é exatamente o problema que o RRF resolve na próxima etapa.
- `ts_rank_cd` é uma aproximação de BM25, não o BM25 canônico - suficiente e honesto pra demo.
